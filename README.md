# ML Prediction Service

Учебный MVP ML-сервиса, приближенный к production-подходу: JWT-аутентификация,
поддержка моделей Scikit-learn, асинхронное выполнение предсказаний, биллинг в
кредитах, аналитический дашборд, мониторинг, Docker Compose и автоматические
тесты.

## Текущее состояние

Репозиторий подготовлен поэтапно на ветке `develop`. Текущая публичная версия
содержит пакет приложения, конфигурацию, health-эндпоинт, схему базы данных,
аутентификацию, базовые REST API-контракты, команды проверки качества, загрузку
моделей, асинхронное выполнение предсказаний, кредитный биллинг, mock-платежи,
промокоды, аналитический дашборд, мониторинг и архитектурную документацию.
Для тестов настроен явный порог покрытия, а приложение быстро завершает запуск
при небезопасных настройках вне локальной среды.

Основная документация начинается с `docs/index.md`.

## Локальный запуск

Создайте и активируйте виртуальное окружение, затем установите проект с
зависимостями для разработки:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

Запустите приложение локально:

```powershell
uvicorn app.main:app --reload
```

Health-эндпоинт доступен по адресу:

```text
http://127.0.0.1:8000/api/v1/health
```

Для текущего локального стенда дашборд доступен по адресу:

```text
http://localhost:18502/
```

## Docker Compose

Соберите и запустите локальную инфраструктуру:

```powershell
docker compose up --build
```

Если на Windows сборка Docker падает из-за пути с не-ASCII символами,
отключите BuildKit для текущей PowerShell-сессии и повторите запуск:

```powershell
$env:DOCKER_BUILDKIT="0"
$env:COMPOSE_DOCKER_CLI_BUILD="0"
docker compose up --build
```

Сервисы:

| Сервис | URL / порт | Назначение |
| --- | --- | --- |
| `backend` | `http://127.0.0.1:18000` | FastAPI-приложение |
| `dashboard` | `http://127.0.0.1:18501` | Streamlit-дашборд при запуске через Docker Compose |
| `prometheus` | `http://127.0.0.1:19090` | Сервер метрик Prometheus |
| `grafana` | `http://127.0.0.1:13000` | Дашборд мониторинга Grafana |
| `postgres` | `127.0.0.1:15432` | База данных PostgreSQL |
| `redis` | `127.0.0.1:16379` | Redis для брокера и хранения результатов |
| `worker` | внутренний сервис | Celery worker |

Остановить сервисы:

```powershell
docker compose down
```

## Миграции базы данных

Примените актуальную схему базы данных:

```powershell
alembic upgrade head
```

Локальный backend в Docker Compose также выполняет `alembic upgrade head` перед
запуском Uvicorn, поэтому чистый запуск compose автоматически подготавливает
базу данных.

Создать будущую миграцию по SQLAlchemy-моделям:

```powershell
alembic revision --autogenerate -m "describe change"
```

Проектирование схемы описано в `docs/database.md`, полная ERD-диаграмма
находится в `docs/erd.md`.

## ML-модели

Аутентифицированные пользователи могут загружать доверенные артефакты моделей
Scikit-learn/joblib/pickle через `POST /api/v1/models`. Загруженные файлы
сохраняются в `MODEL_STORAGE_PATH`, проверяются на наличие вызываемого метода
`predict` и записываются в таблицу `ml_models`.

Сценарий загрузки моделей описан в `docs/ml-models.md`.

## Предсказания

Аутентифицированные пользователи могут создавать асинхронные задачи
предсказания через `POST /api/v1/predictions`. API сразу возвращает задачу со
статусом очереди, а worker сохраняет либо `result_payload.predictions`, либо
ошибку выполнения.

Жизненный цикл предсказаний описан в `docs/predictions.md`.

## Биллинг

Биллинговый слой хранит целочисленные кредиты через баланс пользователя и
неизменяемый журнал транзакций. Для создания задачи предсказания требуется
достаточный баланс, а успешные предсказания списывают настроенную стоимость.
Неуспешные предсказания кредиты не списывают.

Правила биллинга описаны в `docs/billing.md`.

## Платежи

Аутентифицированные пользователи могут создавать mock-платежи через
`POST /api/v1/payments` и подтверждать их через
`POST /api/v1/payments/{payment_id}/confirm`. Подтверждение начисляет кредиты
через журнал биллинга и безопасно при повторном вызове.

Mock-сценарий платежей описан в `docs/payments.md`.

## Промокоды

Администраторы могут создавать промокоды с фиксированным начислением кредитов,
обязательной суммой кредитов, общим лимитом активаций, датой начала и датой
окончания. Позже промокод можно деактивировать. Пользователи могут один раз
активировать действующий промокод в общий кредитный баланс. Успешная активация
создает транзакцию `promo_credit`.

Сценарий промокодов описан в `docs/promo-codes.md`.

## Дашборд

Для текущего локального стенда Streamlit-дашборд доступен по адресу:

```text
http://localhost:18502/
```

При запуске через Docker Compose с портами по умолчанию используется адрес:

```text
http://127.0.0.1:18501
```

Аутентифицированные пользователи попадают в отдельный USER Cabinet со страницами
для обзора, предсказаний, собственных моделей и баланса. Пользователи могут
загружать модели, запускать асинхронные предсказания по CSV или ручным строкам,
обновлять результаты, пополнять баланс mock-платежами, активировать промокоды
и смотреть журнал кредитных операций. Пользователи с ролью admin попадают в
отдельный ADMIN Panel со страницами обзора, пользователей, моделей, платежей,
транзакций, промокодов, настроек только для чтения, мониторинга и логов/ошибок.
Дашборд использует тот же сценарий входа через API, что и Swagger, и обращается
к API backend-сервиса вместо прямого чтения базы данных.

Сценарий дашборда описан в `docs/dashboard.md`.

## Тестирование

Автоматический набор тестов покрывает основные MVP-сценарии: аутентификацию,
API-контракты, загрузку моделей, асинхронные предсказания, биллинг,
mock-платежи, промокоды, агрегацию аналитики, метрики мониторинга и изоляцию
данных между пользователями.

Порог покрытия настроен в `pyproject.toml`; минимальное общее покрытие должно
быть не ниже 70%. Визуальная точка входа Streamlit исключена из порога
покрытия, при этом чистые вспомогательные функции дашборда и все
backend/API-сценарии остаются покрыты автоматическими тестами. Текущий
локальный результат: 95 пройденных тестов и 89% общего покрытия.

Стратегия тестирования описана в `docs/testing.md`.

## Безопасность

Приложение проверяет чувствительные runtime-настройки при запуске. В
нелокальных окружениях debug-режим должен быть отключен, а JWT secret должен
отличаться от placeholder-значения и содержать минимум 32 символа. Выбор
JWT-алгоритма ограничен `HS256`.

Усиление безопасности покрывает некорректные хеши паролей, истекшие токены,
неактивных пользователей, санитизацию имен файлов при загрузке моделей,
скрытие путей хранения и границы владения пользовательскими данными.

Чек-лист безопасности и остаточные риски описаны в `docs/security.md`.

## Бизнес-план

Проект использует предоплаченные кредиты как модель монетизации. Одно успешное
предсказание стоит `1` кредит; неуспешные предсказания не оплачиваются.
Mock-платежи представляют пополнение баланса в MVP, а промокоды с фиксированным
начислением кредитов являются реализованной маркетинговой механикой.

Краткий бизнес-план описан в `docs/business-plan.md`.

## Процесс разработки

Работа сначала ведется в ветке `develop`. Завершенные логические этапы
переводятся в статус `Waiting for Approval` после успешных проверок. Ничего не
пушится в `origin` и не вливается в `main` без явного подтверждения владельца.
